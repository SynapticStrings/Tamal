# 0005 · 判定与诊断分离：digest 当判官，sketch 当法医

**Status**: Accepted（协议层规范；内核代码零改动）

## 背景

源于「曲线存活能否用局部模糊匹配（按形状判相似）」的讨论。一方直觉：
digest 不必是 hash——hash 是「肉泥」，结构全碎，只能回答「完不完全
相同」，回答不了「像不像」「哪里不像」；把采样值/原始数据下采样到
若干抽象点（粒度越粗抽象越厉害）可保留形状信息，全局与局部相似都
可算。

此直觉在表示层面成立（sketch / 感知哈希一族），但必须给「肉泥」和
「抽象点」各划清岗位，否则粗抽象会以更讲究的外观重新引入 tolerance
后门。

## 决策

1. **判定（apply/conflict）只接受精确判等；相似度永远不接自动 apply
   通道。**
   - 合法：`digest(normalize(base))`——归一化是**确定函数**（声明
     分辨率/网格，如「本 channel 的音乐意义单位是 1 cent」），在声明
     的分辨率上任何变化仍产生 conflict。分辨率是 policy 的显式声明，
     确定、可测、可进 conformance 向量。
   - 非法：`distance(sketch, sketch') < ε → apply`——变化明明存在
     却因「够小」被放行，放行的是用户没批准过的决定。把粗粒度 sketch
     直接当判据同属此类：粗抽象 = 隐形阈值（4 点/音符的下采样直接
     抽象掉 vibrato，引擎重生成后 vibrato 全变也「相同」通过）。
   - 判别口诀：归一化是函数（一个确定输出）；相似度是带阈值的谓词
     （变化存在也放行）。前者在声明的分辨率上**从不**静默忽略变化，
     后者会。

2. **sketch（下采样抽象点）的唯一岗位是诊断**，作为 patch 的 sidecar
   在挂载时存储、check 时重算：
   - conflict 解释：两版 sketch 的差异区段可视化；
   - 全局/局部发散分离：逐段比抽象点，哪段散了指哪段；
   - 人工强制重 apply 的决策证据（「发散 2%，要应用吗？」——给人
     看的报告，不是自动通道）。

   即：hash 当判官、sketch 当法医。判官只看同一分辨率下等不等；
   法医负责向活人解释现场。

3. **chunk digest 与 sketch 互补，不替代**：chunk 负责粗定位（哪个
   区块变了），sketch 负责区块内解释（怎么变的、像不像）。

## 对内核的影响

零。`Patch` 只要求 `base_digest` 可判等；归一化与 sketch 都是
Caller/协议层制品：

- 归一化函数写进各 channel 的 policy 规范；digest 本身走 canonical
  digest 规范（README Not yet 第 3 条）。
- sketch sidecar 存于 patch metadata，内核不感知。

## 登记：diff 适配器的诚实规矩

随本次讨论确认，登记于此防止丢失：

- 适配器内部可用三元组式上下文匹配做 1↔1 配对；未配对区段降级为
  merge / split / delete+insert 候选。
- **猜不准时朝「显式死亡」猜（Delete+Insert），不朝「乐观存活」猜**：
  猜死了 anchor 变 conflict 浮到用户面前；猜活了 patch 静默贴到错误
  元素上。一切不确定必须流向冲突，不能流向静默。
- 模糊/相似度作为「给人的建议」合法（conflict 后提示「98% 相似，
  要强制应用吗」），作为自动判据非法——与决策 1 同一条线。
